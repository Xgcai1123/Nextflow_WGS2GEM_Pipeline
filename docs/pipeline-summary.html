NextFlow-WGS2GEM — pipeline reference

Bacterial whole-genome sequencing to a draft genome-scale metabolic model. A Nextflow DSL2 port of the Snakemake WGSpipeline: QC, assembly, annotation, model reconstruction, model evaluation, and one self-contained report.

1 · What it does

One command turns paired-end Illumina reads into a draft model plus the evidence needed to judge it. Eleven pipeline steps, one optional extra one, twelve Nextflow processes. Every per-sample step is an independent branch of a dataflow graph: whatever is ready runs, whatever does not fit the CPU budget queues (see §4 for which steps serialise).

Inputs

A sample sheet (one row per isolate), paired-end FASTQ, reference databases (Bakta, BUSCO), and optionally one public reference genome per isolate.

Outputs

results/: per-step QC, the derived data, the models, the report. data/ is input only; a run writes nowhere else.

Deliverables

results/models/carveme/<sample>/<sample>.xml (the model) and results/report/multiqc_report.html (everything else).

Measured on

Two E. coli isolates: K-12 (SRR1770413) and O157:H7 (SRR10194530). ~38 min on an idle 8-core host.

2 · Project structure

Two roots and nothing else: data/ is what goes in, results/ is what comes out. logs/, benchmarks/, work/ and .nextflow/ are run bookkeeping. Nothing generated is committed.

Two facts about this graph that surprise people. First, steps 1 and 2 are parallel branches off the same input: FastQC is not a gate for trimming, so killing FastQC does not stop the assembly. Second, everything from step 4 onwards is per sample and independent — one sample failing does not stop the other (errorStrategy = 'finish').

4 · Step-by-step contract

For each step: exactly what goes in, what it produces, and who consumes the output. Paths are relative to the project root; <sample> is the sample column of the sheet.

1 · FASTQC_RAW per sample × 2 files

input
data/raw/<fq1>, data/raw/<fq2> — the raw pair, read-only, never modified
tool
FastQC 0.12.1 (--threads $task.cpus)
output
results/qc/fastqc_raw/<sample>_{1,2}_fastqc.html and …_fastqc.zip
consumed by
11 MULTIQC, which parses the two .zip files (the .html is for humans)

Runs in parallel with step 2 — trimming does not wait for this, and a FastQC failure does not stop it. That is why the failure-isolation test kills both entry points.

2 · TRIMMOMATIC per sample

input
the same raw pair (fq1, fq2)
tool
Trimmomatic 0.39, LEADING:3 TRAILING:3 SLIDINGWINDOW:4:20 MINLEN:36 (the original pipeline's settings, verbatim)
output
results/reads/<sample>_R1_paired.fastq.gz, …_R1_unpaired.fastq.gz, …_R2_paired.fastq.gz, …_R2_unpaired.fastq.gz
consumed by
3 FASTQC_TRIMMED (paired only) and 4 SPADES (paired only). The unpaired reads are written for completeness and used by nothing.

3 · FASTQC_TRIMMED per sample × 2 files

input
results/reads/<sample>_R{1,2}_paired.fastq.gz
tool

output
results/qc/fastqc_trimmed/<sample>_R{1,2}_paired_fastqc.{html,zip}

11 MULTIQC (zips)

Exists so the report can show the effect of step 2, not just its success.

4 · SPADES per sample

input

5 · QUAST per sample

input

tool
QUAST 5.2.0, --labels <sample> (mandatory: every input is called contigs.fasta), --min-contig, --threads 1
output
results/qc/quast/<sample>/{report.html, report.txt, report.tsv}
consumed by
11 MULTIQC: report.tsv becomes the QUAST table, report.html is embedded as QUAST: full report

QUAST's own reference mode (-r) is deliberately not used — see §11. Output is byte-identical to the original pipeline.

5b · ASSEMBLY_REF optionalper sample

input
results/assembly/<sample>/contigs.fasta + the FASTA named in that row's reference column (resolved against --ref_dir)
tool
BLASTN 2.17.0 (-task megablast) via scripts/compare_assembly_ref.py; thresholds are QUAST's defaults (identity ≥ 95 %, alignment ≥ 65 bp)
output
results/qc/refcompare/<sample>/<sample>_refcomp.tsv (18 metrics) and …_assembly_ref_mqc.tsv (the report row)
consumed by
11 MULTIQC only

Runs only for rows with a reference: no reference, no task, no report section. A reference that matches nothing fails the task (exit 2) rather than publishing zeroes.

8 · Reading the numbers — the questions everyone asks

Twenty questions, grouped. The full field guide for every column is in docs/interpretation.md.

Method

Why not use QUAST's own reference mode (-r)?

It compiles a bundled minimap2 on first use, and on arm64 macOS that compile fails (-msse2, -mfpu= are x86/Linux flags). QUAST then only warns and silently falls back to reference-independent statistics, and it has no hook for an external aligner. Step 5b therefore does the comparison with BLASTN at QUAST's own thresholds, which also keeps QUAST's output byte-identical to the original pipeline.

Are the genome-fraction numbers comparable with dnadiff?

Conceptually yes, and the thresholds are the same. The aligner differs, so treat 99.38 as "essentially complete", not as a value to compare with a published 99.4.

Why does a low genome fraction not mean a broken assembly?

The reference is a yardstick, not a truth claim. Sakai is one O157:H7 isolate; this project's O157:H7 sample recovers 97.37 % of it at 99.72 % identity with four times the mismatch rate of the K-12 sample — the signature of a different strain of the same serotype. The task fails only when a reference matches nothing.

Why are both samples' growth rates identical?

Both models share CarveMe's template biomass equation and the same declared medium, so the optimum is set by the medium, not by the isolate. Do not use it to compare strains.

Where does the 66 h⁻¹ column come from?

It is CarveMe's shipped medium with all 342 exchange reactions open: the cell imports every amino acid, nucleotide, vitamin and metal, so the objective measures how fast biomass can be assembled from ready-made parts. It is the number that would have been reported as "growth" if nobody declared a medium.

Numbers that look contradictory

Why does one sample appear as five rows in General Statistics?

FastQC runs per FASTQ file (four per sample); assembly and model steps run per sample. The aggregate table has one row per entity, so an isolate appears as SRR1770413 plus _1, _2, _R1_paired, _R2_paired. Blank cells mean "not applicable at this granularity".

There are two GC columns — which is the genome's?

Assembly GC (%) (QUAST, 50.34). Reads GC (%) is measured on the reads (FastQC, 50). They agree here, which is the expected sanity check; a divergence points at contamination or a wrong species.

L50 is a count — why does it print 8.0?

MultiQC formats every numeric column with one decimal; the header says (contigs). It used to be worse: the QUAST module scales count columns to thousands, so an L50 of 8 printed 0.0 K. The overlay now sets quast_config.total_number_contigs_multiplier: 1.

MEMOTE total is 68.1 % — is the model 68 % correct?

No. It is a weighted score over 12 consistency and annotation tests, not a fraction of anything physical. The biomass/growth/medium tests carry weight 0 in MEMOTE 0.17.0, so they cannot move it — which is exactly why step 9 exists.

The table says 2486 reactions, the embedded MEMOTE report says 2496. Which is wrong?

Neither. COBRApy creates 10 exchange reactions on load for metabolites that have none in the file (na1, ni2, cd2, cm, hg2, fusa, gbbtn, novbcn, doxrbcn, ttrcyc). The SBML has 2486; MEMOTE sees 2496. Quote which one you mean.

BUSCO says 100 % complete, but genome fraction is 97.4 %. Contradiction?

No. BUSCO asks "are the 440 conserved genes present?"; genome fraction asks "how much of the reference sequence did I recover?". A complete gene set can sit on an assembly that is missing accessory regions — which is the O157:H7 case.

440/440 complete yet 2 duplicated — is the sample contaminated?

D = 2 means two markers occur more than once; the complete count still includes them. Two is within normal short-read variation. More than ~5 % would be worth investigating.

Only 30.5 % of the K-12 contigs align — is the assembly bad?

No, and this is the most misread number in the report. Those 113 aligned contigs carry 94.45 % of the assembly's bases; the remaining ~257 are tiny fragments, often below the 65 bp alignment threshold. Read Genome fraction for completeness.

Duplicates (%) 12–15 % — is that high?

Normal for short-read libraries, and it inflates apparent coverage only slightly. Compare raw with trimmed: trimming does not change it, which is expected (duplicates are mostly PCR artefacts, not adapters).

Modules failed (%) 10–20 % — did 20 % of the reads fail?

No: it is the share of FastQC modules that failed for that file. It drops to 0 % after trimming, which is the useful signal.

Assembly 5.40 Mbp vs reference 5.59 Mbp, yet genome fraction 97.4 % — consistent?

Yes: 97.4 % of 5.59 Mbp ≈ 5.45 Mbp of the reference is covered. The assembly is shorter because it lacks ~190 kbp of accessory sequence present in Sakai (and carries a little of its own). Coverage of a shorter genome is what a different strain looks like.

Why is the growth check missing from the runtime table?

It writes no benchmarks/ record: that directory is the Snakemake step set, and an unknown label would appear as a raw column. Its cost is seconds; the log timestamps are the record. The same applies to the reference comparison.

Why do the numbers contain spaces, e.g. 2 486?

MultiQC's thousand separator: 2486. (The report normaliser deliberately leaves numeric separators alone.)

Annotation · genes is 33.3 % for both models — a red flag?

A property of CarveMe drafts, not of the data: gene-associated annotations and SBO terms are sparse in reconstructed models, and identical across isolates because both came through the same reconstruction path.

Provenance

Which medium, and where did its composition come from?

media/m9_aerobic.yaml: the 20 compounds are taken verbatim from CarveMe's own media_db.tsv row M9 (carveme 1.6.6, sha256 recorded in docs/asset-sources.md). The uptake rates (glucose 10, O₂ 20, the rest 1000 mmol·gDW⁻¹·h⁻¹) are a documented project convention, not measurements. The growth rate depends on them — 0.476 / 0.953 / 1.283 / 28.772 h⁻¹ for a glucose bound of 5 / 10 / 20 / unlimited — while the yield (0.529 g/g) does not, which is why plausibility is argued from the yield.

Which reference genomes, and how are they pinned?

GCA_000005845.2 (E. coli K-12 MG1655, 4,641,652 bp, one sequence) and GCA_000008865.2 (E. coli O157:H7 Sakai, 5,594,605 bp, chromosome + pOSAK1 + pO157), fetched from NCBI Datasets. Accession, length and md5 are recorded in docs/asset-sources.md; the FASTAs are git-ignored.

10 · Quality gates

Seven tool-free checks and four CI jobs. CI runs the same scripts a developer runs, so the two cannot drift apart.

checkwhat it protects
run-lint.shnextflow lint: zero errors, and a warning count that cannot grow past a pinned baseline
run-preview.shcompilation plus seven malformed sample sheets, each aborting before a single task
run-disk-guard.shthe disk pre-flight: passes, aborts before any task, and is disabled by 0
run-stub-smoke.shthe whole DAG (25 tasks in the CI fixture) runs with stubs, publishes the documented tree, asserts the growth-check-before-MEMOTE edge, and never touches the validated output tree
run-failure-isolation.shan injected failing sample: exit 1, no partial deliverables, finished work survives, -resume converges
run-embed-check.shthe report embedders and the header normaliser actually run: section headers, one-file vs per-sample, byte-identical srcdoc round-trip, no CSS/JS leakage, header renaming, unit stripping, idempotence
run-growth-check.shthe medium and its checker, with three negative controls that must each fail: unmappable component, impossible window, physical-bound violation

The guards are mutation-tested: each was shown to fail when the thing it protects is broken. One of them was caught doing exactly that in CI — a failure-injection test had been passing through an empty path because it killed only one of two parallel entry points.

11 · Limits and open items

itemstatus
QUAST's own reference modecannot run here: bundled minimap2 fails to compile on arm64 macOS. Replaced by step 5b.
The SBML omits 10 exchange reactionsCOBRApy creates them on load. A downstream tool that does not would report missing medium components (na1, ni2 are in M9). Documented, not patched.
Growth windowreported, not fatal: the 0.4–1.5 window is E. coli-specific and the pipeline accepts other organisms. An unmappable medium stays fatal (exit 2).
Growth rate vs mediumthe rate is conditional on the uptake bounds (a convention); the yield is the robust number. Both are asserted; the sensitivity table is in the medium file and in the interpretation guide.

# one cohort, no reference comparison
nextflow run . \
    --raw_dir   /path/to/fastq \
    --bakta_db  /path/to/bakta/db-light \
    --busco_db  /path/to/busco/db

# with the optional assembly-vs-reference comparison

# operational switches
-resume                     reuse finished tasks
-profile lowmem             halve SPAdes/Trimmomatic threads (two samples assemble concurrently)
--min_free_disk_gb=0        skip the disk pre-flight (it needs 20 GiB by default)
--report_tag run2           a second report that coexists with the first

Requirements

  • Nextflow ≥ 25.10 (developed and validated on 26.10.0)
  • conda or mamba on PATH — 8 environments are built automatically on the first run
  • Java 17+ (inside the Trimmomatic environment)
  • ≥ 20 GiB free disk, enforced before any task starts
  • Bakta database and a BUSCO lineage cache, by parameter; NCBI references optional

Failure behaviour

errorStrategy = 'finish': a failing task always fails the run (non-zero exit), the failed sample leaves no downstream deliverables, the healthy sample's finished work survives, and -resume converges while reusing it. A missing sample-sheet column, a missing FASTQ, a missing reference or a full disk all abort before the first task.
