这份文档只回答一个问题:**凭什么这么做。**

它和另外三份的分工:

| 文档 | 回答的问题 | 读者 |
|---|---|---|
| `README.md` | 怎么跑、参数默认值是什么 | 使用者 |
| `docs/interpretation.md` | **这个数字怎么读**、多少算好 | 拿到报告的人 |
| **本文** | **为什么用这个工具、为什么是这个参数** | 答辩 / 审稿 / 合作者质疑时 |
| `docs/nextflow-port-design.md` | 为什么这样移植、踩过哪些坑(编号 F/D) | 维护者 |

## 0. 怎么用(三档,别一上来读全文)

**第一档 · 30 秒**:每步只看「一句话」,12 句话,能撑住"你们这管线做了什么"。
**第二档 · 3 分钟**:加看「为什么是它」+「参数」。
**第三档 · 深挖**:加看「不这样会怎样」+「审稿人会问」,括号里的 F/D 编号指向设计文档。

**万能句式**(忘了一切时用这一句):

> "这一步的参数不是我们调出来的,是从原管线 **1:1 移植**过来的,目的是让输出能和原管线逐字节对比;我们自己新增的两步(参照比对、生长验证)另有文献和实测依据,写在设计文档 F30 / F26。"

这句话之所以有力量,是因为它**可验证**:`docs/port-parity` 的记录、逐字节对比、CI 都在仓库里。

## 1. 先承认一个前提:这些参数大部分不是"最优选择"

这套管线是 **Snakemake 版的等价移植**。移植的第一原则是**保真**(faithfulness),不是优化:任何参数一改,输出就不能和原版逐字节对比,"等价"这个结论就作废了。

所以三类东西要分清 —— **答辩时被问倒,几乎都是因为把第三类说成了第一类**:

| 类别 | 含义 | 依据强度 | 怎么回答 |
|---|---|---|---|
| **【移植】** | 原管线就这么写,我们照搬 | 强(可对拍) | "原管线的值,未重新优化;改它就要重跑并重新对拍" |
| **【工具默认】** | 上游作者定的默认值,我们没额外声明 | 中(可追到手册) | "工具默认值,我们没有额外加约束" |
| **【我们的约定】** | 我们自己定的,没有实验依据 | **弱 —— 必须明说** | "这是约定不是测量值;它影响绝对值,所以我们的结论只到'合理'不到'准确'" |

> **一条铁律**:属于第三类的,永远不要包装成"有依据"。审稿人一旦发现你在弱依据上说硬话,后面所有数字都会被怀疑。第 9 步的生长速率就是这类,见 §3.10。

## 2. 参数三分类表(被问得最多的那张表)

| 参数 | 值 | 类别 | 依据 / 说明 |
|---|---|---|---|
| Trimmomatic `LEADING/TRAILING` | 3 / 3 | 【移植】 | 去掉两端质量 ≤3 的碱基(Phred 3 ≈ 99.9% 错误率) |
| Trimmomatic `SLIDINGWINDOW` | 4:20 | 【移植】 | 4 碱基窗口平均质量 <20 就切掉后面 |
| Trimmomatic `MINLEN` | 36 | 【移植】 | 短于 36 bp 丢弃;36 也是 Illumina 的保守下限 |
| Trimmomatic `ILLUMINACLIP` | TruSeq3-PE:2:30:10 | 【移植】 | 接头表 + 2 个错配容差 + 两个模式阈值 |
| Trimmomatic `-phred33` | — | 【移植】 | Illumina 1.9+ 使用 Phred+33 编码 |
| SPAdes `--careful` | 开 | 【移植】 | 组装后做错配修正,减少 SNP 级错误;代价是更慢更吃内存 |
| SPAdes 输入 | 只用 paired | 【移植】 | unpaired reads 不参与组装,避免单端污染 |
| QUAST `--min-contig` | 0 | 【我们的约定】 | 计**所有** contig。设 500 会让"contig 数"好看但失真 |
| BUSCO lineage | `enterobacterales_odb10` | 【移植】 | 440 个单拷贝直系同源基因,匹配肠杆菌目 |
| Bakta DB | `db-light`(4 GB) | 【我们的约定】 | 不用 db-full(约 30 GB);代价是少部分专业注释 |
| CarveMe solver | `scip` | 【我们的约定】 | 免费可用;cplex/gurobi 需授权 |
| MEMOTE solver | `glpk` | 【我们的约定】 | 同上 |
| 参照比对阈值 | ≥95 % 一致 / ≥65 bp | 【工具默认】 | 照搬 QUAST/dnadiff 的默认,让数字可与标准流程比较 |
| 生长培养基 | M9 好氧,20 个化合物 | 【工具默认】+【我们的约定】 | 成分取自 CarveMe 自己的 `media_db`,**不是我们编的** |
| 摄取上限 uptake | 葡萄糖 10 / O₂ 20 / 矿物 1000 | **【我们的约定】** | **无实验依据**,见 §3.10 —— 答辩时必须主动声明 |
| `min_free_disk_gb` | 20 | 【我们的约定】 | 工程决定:磁盘不足时 SPAdes 会静默失败(实测) |
| 线程数 | 8/4/2/1 | 【移植】 | 即使不准也照搬,否则耗时不可比 |

## 3. 十二步,每步五问

### 3.1 FASTQC_RAW(第 1 步)

- **一句话**:原始数据长什么样、有没有系统性测序问题。
- **为什么是它**:FastQC 是这个领域的默认体检工具,报告里是每条 read 位置的质量分布、GC 分布、接头污染等。
- **参数**:只有 `--threads`,没有阈值。
- **不这样会怎样**:没有"修剪前"的基线,后面就无法证明修剪起了作用。
- **审稿人会问**:*"FastQC 报 fail 为什么不终止?"* → 因为 FastQC 的 fail 是**启发式**判断,不是共识阈值;我们把它当**证据**放进报告,不当门禁。用固定阈值当门禁会造成大量假阳性,还会掩盖真正的问题。

### 3.2 TRIMMOMATIC(第 2 步)

- **一句话**:去掉接头和低质量碱基,且保持 R1/R2 配对。
- **为什么是它**:它是原管线的选择,而且**参数是显式的、可审计的** —— 不像自动调参的工具,你能在报告里指出每一个阈值。
- **参数**(逐个翻成人话):
  - `LEADING:3 / TRAILING:3` —— 开头/结尾质量低于 3 的碱基剪掉;
  - `SLIDINGWINDOW:4:20` —— 4 个碱基的滑动窗口,平均质量低于 20 就把后面全切掉;
  - `MINLEN:36` —— 剪完短于 36 bp 的整条丢弃;
  - `ILLUMINACLIP:TruSeq3-PE.fa:2:30:10` —— 接头表 + 允许 2 个错配 + 两个模式阈值。
- **不这样会怎样**:接头残留会被组装成假 contig,低质量尾部会被拼成嵌合序列 —— 两者都会变成下游的**假基因**,最终变成模型里的假反应。
- **审稿人会问**:*"MINLEN 36 怎么来的?"* → 诚实答:原管线的值,我们没有重新优化;36 同时是 Illumina 的保守下限。**不要**声称我们做过参数扫描。

### 3.3 FASTQC_TRIMMED(第 3 步)

- **一句话**:修剪有效吗?有没有剪过头?
- **为什么是它**:同一个工具、同一组指标,前后才可比。这是"证据链"的关键一环。
- **参数**:同 3.1,无阈值。
- **不这样会怎样**:只能相信"修剪应该有用",拿不出证据。
- **审稿人会问**:*"为什么要跑两遍?"* → 因为前后对照才构成证据;两份结果在报告里并列展示。

### 3.4 SPADES(第 4 步)

- **一句话**:把短读拼成 contigs。
- **为什么是它**:细菌分离株短读组装的常用工具,`--careful` 模式专门为高覆盖数据降低错配。
- **参数**:`--careful`(组装后做错配修正)、`-1/-2` 只用 paired、`--threads 8`。
- **不这样会怎样**:错配 → 注释出假基因 → 模型里多出假反应。这是"错误会一路传到最终结论"的典型。
- **审稿人会问**:*"N50 只有 159 kbp,是不是拼得很碎?"* → 对 `--careful` + 短读 + 4.8 Mbp 基因组属正常范围;真正的反驳证据是 **BUSCO 440/440**(基因空间完整)和 **参照比对 99.38 %**(覆盖完整),不是 N50。

### 3.5 QUAST(第 5 步)

- **一句话**:拼装体的统计特征:N50、L50、contig 数、GC、总长。
- **为什么是它**:组装统计的事实标准,且能嵌入报告。
- **参数**:`--min-contig 0`(计所有 contig)、`--labels <sample>`(保证每个样本标注正确)。
- **不这样会怎样**:没有独立的组装质量证据;`--labels` 缺失会让多样本的数字互相串。
- **审稿人会问**:*"--min-contig 0 是不是在凑数?"* → 相反:设 500 才是"凑数"(只算长的,数字变好看)。我们选择**如实计全部**,并在报告里同时给出总长和 contig 数,让读者自己判断。

### 3.6 ASSEMBLY_REF · 参照比对(第 5b 步,**我们新增**)

- **一句话**:拼出来的东西和一个已知的"真基因组"差多少。
- **为什么是它**:QUAST 自带 `-r` 在 arm64/macOS 上会因为 minimap2 编译失败而**静默降级**成"不含参照的统计"(F30/D20)—— 静默降级是这套管线最不能接受的行为。所以用 BLASTN 自己算,并且**没有比对结果就报错退出**。
- **参数**:≥95 % identity、≥65 bp —— 照搬 QUAST/dnadiff 的默认值,目的是**让数字能和别人的标准流程比**。
- **不这样会怎样**:只能回答"拼得整不整齐",回答不了"内容对不对"。
- **审稿人会问**:*"为什么不去做变异检测?"* → 我们评估的是**组装完整度**,不是株内变异;97.37 % 覆盖一个 O157:H7 参考,读作"这是同血清型的不同株",不是"组装坏了"(见 `interpretation.md` §4.3)。

### 3.7 BUSCO(第 6 步)

- **一句话**:这 440 个几乎所有肠杆菌都有、且只该有一份的基因,你拼出来了多少?
- **为什么是它**:单拷贝直系同源基因集是"基因空间完整度"的行业标准度量。
- **参数**:`-m genome`(先预测基因再比对)、lineage `enterobacterales_odb10`、`--cpu`。
- **不这样会怎样**:只有 contiguity(拼得多长),不知道有没有丢基因。
- **审稿人会问**:*"100 % 是不是太完美了?"* → 这 440 个是高度保守的单拷贝基因,对 *E. coli* 预期就是 100 %。它测的是"这些保守基因在不在",**不测**"你的注释对不对"—— 这是两件事,别混着答。

### 3.8 BAKTA(第 7 步)

- **一句话**:基因在哪、分别是什么。
- **为什么是它**:维护活跃、输出完整(GFF3 / 蛋白 FAA / 核酸 FFN / GenBank / TSV / TXT),而且**它产出的 `.faa` 正是下一步 CarveMe 的输入**。
- **参数**:`--db data/db/bakta/db-light`,`version.json` 作为数据库升级哨兵(库一升级,任务哈希就变,不会偷用旧结果);外面套了一层 AMR-guard,绕开上游 AMRFinderPlus 已知崩溃。
- **不这样会怎样**:没有蛋白序列,代谢模型无从谈起。
- **审稿人会问**:*"db-light 会不会漏基因?"* → 会少部分专业注释(某些 AMR/小分子相关);所以 AMR 单独用 guard 处理,并且这个限制写在 `interpretation.md` 的"限制"里,不藏。

### 3.9 CARVEME(第 8 步)

- **一句话**:从蛋白序列自动"雕"出一个基因组尺度代谢模型(draft GEM / SBML)。
- **为什么是它**:基于 UniProt 模板库做自动化 carve,不需要逐反应人工 curation —— 这是让"从测序到模型"能全自动的前提。求解器用 SCIP(免费)。
- **参数**:`--solver scip`;输入是 `.faa`(不是 contigs)。**输入先拷进自己的私有目录**——CarveMe 会按输入路径推导 diamond 输出文件名,如果直接吃 Bakta 的 `.tsv` 就会把注释文件覆盖掉(真事故,已修)。
- **不这样会怎样**:没有模型,后面两步和整份报告的核心都没了。
- **审稿人会问**:*"自动生成的 draft 模型可信吗?"* → draft 就是 draft:必须配 MEMOTE 分数(§3.11)+ 生长验证(§3.10)才敢用。我们从不声称它等价于人工 curation 的模型。

### 3.10 GROWTH_CHECK · 生长验证(第 9 步,**我们新增,也是最需要坦白的一步**)

- **一句话**:这个模型在**指定的培养基**上到底能不能长?长多快?
- **为什么必须要这一步**:MEMOTE **不测生长**。而 CarveMe 交出来的模型默认把 342 个交换反应**全部打开**(等于完全培养基),这时它会长到 **66 h⁻¹** —— 一个一眼假、但看起来很厉害的数字(F25/D16)。没有这一步,报告会说谎。
- **参数**:
  - 培养基 **M9 好氧**:20 个化合物取自 **CarveMe 自己的 `media_db.tsv`**(不是我们编的配方);
  - 摄取上限:葡萄糖 10、O₂ 20、矿物 1000 —— **【我们的约定】,没有实验依据**;
  - 断言:生长率必须落在合理窗口、去掉碳源必须为 0、厌氧必须更低、不得超过物理上限 2.81 h⁻¹(已知最快细菌 *V. natriegens*)。
- **不这样会怎样**:报告里出现 66 h⁻¹ 这种数;所有下游结论(能不能产某个产物)都建立在荒谬的边界条件上。
- **审稿人会问**:*"葡萄糖摄取 10 凭什么?"* → **标准答法,照这个说**:
  > "这是约定,不是测量值。它决定生长的**绝对值**;所以我们用这条管线得出的结论是'生理上合理',不是'定量准确'。真正可以和文献比的是**生物量产率** —— 我们算得 0.53 g/g(葡萄糖),文献对大肠杆菌最小培养基约 0.5 g/g,这才是一致性证据。"

### 3.11 MEMOTE(第 10 步)

- **一句话**:这个模型的"体检报告"——结构一致性、可模拟性、通量一致性等。
- **为什么是它**:目前唯一被广泛接受的 GEM 质量评分体系,而且**分块**报告,能定位问题在哪。
- **参数**:solver `glpk`(免费);总分是加权百分制。
- **不这样会怎样**:无法判断模型能不能用,只能凭感觉。
- **审稿人会问**:*"68 分算好模型吗?"* → 对**自动重建的 draft**属正常区间(人工 curation 的模型通常高得多)。正确的答法是看**分块**:哪一块失分、失分意味着什么,而不是拿总分和别人比。

### 3.12 MULTIQC(第 11 步)

- **一句话**:把 11 个工具的输出汇成**一份自包含 HTML**。
- **为什么是它**:单文件、可离线打开、可直接发给合作者;章节顺序按管线步骤排(F21/F24)。
- **参数**:喂给它的文件是**按样本表生成的显式列表,不是目录扫描** —— 所以子集运行会得到一致的子集报告,不会把上一次的样本"泄漏"进来。
- **不这样会怎样**:12 个工具的结果散在 10 个目录里,没人会去逐个打开。
- **审稿人会问**:*"这个报告能当补充材料吗?"* → 可以,15 MB 自包含;但要知道 MEMOTE 和 QUAST 的完整页面是以 iframe 形式嵌入的。

## 4. 十个最容易被问倒的问题(标准答法)

1. **"为什么不用 fastp / Unicycler / Prokka?"**
   → 因为这是等价移植,换工具会让"与原管线逐字节对比"这个论证作废。**不是**说它们更差。
2. **"参数为什么不做优化/敏感性分析?"**
   → 移植的第一原则是保真。要做优化必须作为**新版本**重跑并重新对拍,不能偷偷改。
3. **"生长速率 0.953 h⁻¹ 有实验依据吗?"**
   → 没有。它依赖我们设定的摄取上限(约定)。可与文献比的是产率 0.53 g/g。
4. **"MEMOTE 68 分算好吗?"**
   → 对自动 draft 属正常;看分块,不比总分。
5. **"N50 159 kbp 是不是组装很差?"**
   → 用 BUSCO 440/440 和 99.38 % 参照覆盖反驳,而不是辩护 N50。
6. **"97 % 覆盖率是不是丢了基因?"**
   → 是**不同株**(同血清型),不是组装失败;BUSCO 完整度是另一条独立证据。
7. **"FastQC fail 为什么不停?"**
   → 它的 fail 是启发式,不是共识阈值;我们用它作证据,不用它作门禁。
8. **"为什么比原来的管线多了两步?"**
   → 5b 补"内容对不对",9 补"模型能不能长";两步都有编号和实测(F30/F26),并且是**可选/可关**的。
9. **"工具版本为什么不升级?"**
   → 复用资产保持逐字节一致(D4),升级会让历史结果不可比;升级要作为一个版本动作整体做。
10. **"这个结果能重复吗?"**
    → 报告里有完整版本表(引擎 + 12 个工具)、参数、以及 CI 守着的回归检查;`-resume` 是任务哈希,不是时间戳。

## 5. 行话小词典(报告里出现、但没人给你解释的词)

| 词 | 一句话解释 |
|---|---|
| **contig** | 拼出来的连续片段。一个基因组通常被拼成几百个 contig,而不是一条完整染色体 |
| **N50** | 把 contig 从长到短排,累加到总长一半时的那个长度。越大越"整",但不代表越"对" |
| **L50** | 达到 N50 需要几条 contig。越少越整 |
| **genome fraction** | 参考基因组的百分之多少被你拼出来了 |
| **identity** | 比对上的部分,碱基一致的比例 |
| **BUSCO 完整/重复/碎片/缺失** | 440 个保守基因里,找全的 / 找到两份的 / 只找到半截的 / 完全没找到的 |
| **MEMOTE 总分** | 模型各项检查的加权百分制。**是一个相对指标,不是"正确率"** |
| **blocked reaction** | 因为缺代谢物或方向限制,在模型里**永远不可能有通量**的反应 |
| **exchange reaction** | 物质进出细胞的"门"。把门全打开 = 完全培养基 = 66 h⁻¹ 的来源 |
| **biomass reaction** | 模型里代表"长出一份细胞"的假想反应;它的通量就是生长速率 μ |
| **μ(h⁻¹)** | 比生长速率。0.95 h⁻¹ ≈ 倍增时间 44 分钟 |
| **yield(g/g)** | 每克葡萄糖产出多少克细胞干重。**这个量才方便和文献比** |
| **uptake bound** | 每种营养最多能进多快。**这是模型的边界条件,不是测量值** |
| **Phred 33 / Q20** | 碱基质量打分;Q20 = 错误率 1 % |
| **sliding window** | 滑动窗口:连续几个碱基的平均质量低于阈值就切 |

## 6. 一句话总结这份文档的立场

> 这套管线里,**大部分参数不是我们的发明,是我们选择保留的**;我们自己加的两步,依据写在编号里;少数几个(培养基摄取上限、db-light、免费求解器)是**约定**,它们影响绝对值、不影响方向性结论 —— 而这一点,我们主动写在报告和文档里,不等你来问。
